## 2024-05-22 - Replacing Blocking Alerts with Accessible Inline Validation
**Learning:** Found a pattern where form validation used a blocking `alert()` dialog (e.g., in the guestbook submission). This is a known accessibility and UX anti-pattern as it traps keyboard focus unexpectedly, interrupts the user's flow, and doesn't clearly associate the error with the problematic fields.
**Action:** Replaced the `alert()` with an inline error message (using `role="alert"`) positioned near the inputs, and added clear visual feedback (inline red borders using the existing `#c04040` design token) and semantic state (`aria-invalid="true"`) to the specific inputs that failed validation. Ensured that `aria-label`s were also present for the inputs. Used input event listeners to dynamically clear the error states as the user corrects their input. This pattern should be consistently used across any other forms in the application.
